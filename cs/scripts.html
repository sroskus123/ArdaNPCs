Návod 05 1.1.0

Skripty NPC

Události, přehled API a hotové příklady pro léčení, podmínky, questy a poštu.

První skript

Skripty ArdaNPCs 1.1.0 jsou serverové události s vlastním omezeným JavaScript API. Upravuje je důvěryhodný správce s oprávněním OP 2. Skript z CustomNPCs nelze prostě vložit beze změn: názvy událostí a dostupné objekty se liší.

  1. Otevřete editor NPC a tlačítko Otevřít skripty….
  2. Vyberte událost interact. Vložte jen tělo události, například api.message("Vítej!");. Nepřidávejte obal function interact(e) { ... }.
  3. Použijte Kontrola pro syntaxi všech událostí. Test simuluje vybranou událost se správcem jako hráčem; nemění svět, proměnné, časovače, questy ani poštu.
  4. Přepněte Skripty: zapnuto a stiskněte Uložit. Počkejte na potvrzení serveru. Zapnutí je společné pro všechny události NPC.
  5. Zavřete editor a vyvolejte skutečnou interakci. Výsledek i chyby sledujte přes Výpis.

Test nenahrazuje hraní: používá pomocné hodnoty jako event.timer = "test", takže nemusí projít větví s vaším skutečným ID. Příklady níže zkoušejte nejprve v kopii světa. Pokud už událost obsahuje kód, spojte potřebné bloky; vložení nového příkladu přes původní text jej přepíše.

Společná pole jsou event.type, npcId, npcName, hasPlayer, playerId a playerName. Používejte je s prefixem event.. Bez hráče je ID prázdné; před hráčským API ověřte event.hasPlayer. Identitu všech druhů hostů popisují event.hostId, hostKind, hostName a ownerNpcId. API neposkytuje objekty Minecraftu ani Javy.

Přehled běžného API

V ID předmětů, efektů a zvuků používejte úplný namespace, například minecraft:bread. Klíče proměnných a názvy timerů mají 1–48 znaků z [A-Za-z0-9_.:-]. V predicate jsou povolená pouze čtení; změna dat, timeru, questu nebo světa vyvolá chybu.

Příklad: léčitel s odpočtem

Do interact vložte:

if (!event.hasPlayer) return;
if (api.playerGet("heal_wait") === "1") {
    api.message("Na další léčení si chvíli počkej.");
    return;
}
api.playerSet("heal_wait", "1");
api.timer("heal:" + event.playerId, 30, false);
api.heal(8);
api.message("Tvé rány se hojí.");

Do timer téhož NPC vložte:

if (event.hasPlayer && event.timer === "heal:" + event.playerId) {
    api.playerRemove("heal_wait");
}

První klik vyléčí až 8 bodů zdraví (4 srdce). Další léčení povolí jednorázový timer po 30 herních sekundách. Název obsahuje UUID hráče, takže se hráči navzájem nepřepisují. Timer čeká, když NPC není načtené nebo hráč není online. Na jedno NPC připadá nejvýše 16 timerů včetně ostatních skriptů; tento jednoduchý příklad je pro malé skupiny.

Příklad: podmínka podle XP

Do predicate vložte:

return event.key === "experienced"
    && event.hasPlayer
    && api.playerLevel() >= 5;

V podmínkách dialogu nebo questu zvolte SCRIPT_PREDICATE a klíč experienced. Podmínka projde hráči od XP úrovně 5. Každá cesta musí vrátit true nebo false; nic zde neposílejte ani neukládejte. Pro jednoduché číselné proměnné lze použít SCRIPT_VARIABLE_MIN s klíčem player:nazev nebo npc:nazev.

Příklad: ruční cíl questu

Nejdříve na tomto NPC vytvořte quest a přidejte cíl typu MANUAL s požadovaným počtem 1. Opište skutečné ID questu a cíle z editoru; ID cíle se generuje automaticky. V ukázce nahraďte patrani skutečným ID questu a stopa_les skutečným ID cíle. Hráč musí quest přijmout. Upravený kód vložte do interact:

if (api.questProgress("patrani", "stopa_les", 1)) {
    api.message("Zaznamenání stopy bylo zařazeno.");
} else {
    api.message("Tuto stopu teď zaznamenat nepotřebuješ.");
}

true znamená přijetí do fronty, nikoli potvrzený zápis. Po skutečném kliku ověřte deník questu. Neaktivní nebo hotový cíl a dosud zamčený krok SEQUENTIAL vrátí false; neexistující quest nebo nesprávný typ cíle je chyba konfigurace. Nenahrazujte skutečný questový stav vlastní proměnnou „hotovo“.

Příklad: příběhový dopis

Do interact NPC vložte:

if (api.mail("Pozvání", "Vrať se ke strážci pro další úkol.", "chapter1_invitation")) {
    api.message("Dopis je ve frontě. Zkontroluj schránku.");
}

Stabilní klíč brání opakovanému dopisu pro stejné NPC a hráče. false může znamenat již použitý klíč, plnou schránku nebo limit; není to potvrzení doručení. Příjemcem je hráč události. Skriptované předměty a bloky potřebují pro poštu i questový postup existujícího vlastníka NPC.

Ukládání a provozní limity

  • Jedna událost: 12 288 znaků; všechny události: 32 768 znaků. Jeden běh: 60 000 instrukcí. NPC, předměty a bloky sdílejí serverové rozpočty, včetně 64 událostí za tick.
  • Prostor NPC/instance nebo instance + hráč: 64 klíčů, 1024 znaků hodnoty, celkem 16 384 znaků. V celém světě nejvýše 4096 těchto prostorů.
  • 16 timerů na hosta a 1024 celkem. Timery používají herní čas, přežívají restart a nedohánějí vynechaná opakování.
  • Nejvýše 8 vnějších efektů a 2 vyvolaní mobové na událost. Další minutové kvóty omezují spam.

Kód se ukládá s konfigurací NPC, stav a timery do <world>/data/ardanpcs/scripts-state.json. Klon převezme kód, ale má nové UUID a vlastní prázdný stav. Proměnné a timery se potvrzují před účinky ve světě; pád serveru mezi těmito kroky může znamenat neprovedený účinek. Nejde o záruku společné transakce všech systémů.

Chybná událost zablokuje skripty daného hosta. Opravte chybu podle diagnostiky a znovu uložte. Neprověřený cizí kód nepouštějte: prostředí je omezené, ale běží ve stejném procesu jako server. Java, soubory, síť, příkazy, eval, konstruktory new a část běžného JavaScriptu nejsou dostupné. Pokračujte na skriptované předměty a bloky nebo řešení problémů.
